## 1. Backend — `ExtractBriefingUseCase`

### O que faz

Fallback manual para quando o WhatsApp não dispara a extração automaticamente.
Busca transcript acumulado no Redis (`whatsapp:transcript:{briefingId}`), valida estado
`COLLECTING`, enfileira `briefing.extract` na BullMQ.

### Arquivo novo

`apps/api/src/application/briefing/ExtractBriefingUseCase.ts`

```typescript
// Injeta: briefingRepo, queue, redis
export class ExtractBriefingUseCase {
  async execute(cmd: {
    briefingId: string;
    operatorId: string;
    correlationId: string;
  }): Promise<Result<{ briefingId: string; status: "queued" }>>;
}
```

**Validações:**

- Briefing existe → `NotFoundError` se não
- `briefing.status === 'COLLECTING'` → `DomainError('INVALID_STATE')` se não
- Transcript no Redis não vazio → `DomainError('VALIDATION_ERROR', 'transcript vazio')` se não

**Sem novo domain event.** O enqueue do `briefing.extract` já dispara o flow existente.

### Rota nova

`briefings.routes.ts` — adicionar:

```
POST /api/v1/briefings/:id/extract
Auth: authMiddleware
Body: {} (vazio)
200: { data: { briefingId, status: "queued" }, meta }
404: briefing não encontrado
409: status != COLLECTING
422: transcript vazio no Redis
```

### API client (web)

`apps/web/src/lib/api.ts` — adicionar em `api.briefings`:

```typescript
briefings: {
  list: (token) => request<{ data: any[]; meta: any }>("/briefings", { token }),
  getById: (id, token) => request<{ data: any; meta: any }>(`/briefings/${id}`, { token }),
  extract: (id, token) => request<{ data: any }>(`/briefings/${id}/extract`, {
    method: "POST", body: JSON.stringify({}), token
  }),
  approve: (id, token) => request<{ data: any }>(`/briefings/${id}/approve`, {
    method: "PATCH", body: JSON.stringify({}), token
  }),
},
```

createdAt, updatedAt`. Sem `clientName` — usar `id.slice(-8)` como fallback.

## 3. Frontend — `/briefings`

**Arquivo:** `apps/web/src/app/(dashboard)/briefings/page.tsx`

### Layout

```
Briefings                           [título + subtítulo]

┌──────┬──────────────┬────────────┬─────────────┬──────────┐
│ ID   │ Cliente      │ Status     │ Iniciado    │ Ação     │
├──────┼──────────────┼────────────┼─────────────┼──────────┤
│ #abc │ João Silva   │ COLLECTING │ 12/06 14:00 │[Extract] │
│ #def │ Maria Ltd    │ APPROVED   │ 11/06 10:30 │    —     │
│ #ghi │ Tech Corp    │ REJECTED   │ 10/06 09:15 │    —     │
└──────┴──────────────┴────────────┴─────────────┴──────────┘
```

**Status badges:**

- `COLLECTING` → amber (aguardando WhatsApp)
- `APPROVED` → emerald
- `REJECTED` → destructive
- `PENDING_REVIEW` → sky

**Botão Force Extract:** visível **somente** para `status === 'COLLECTING'`.
Ao clicar: loading inline (`<Loader2 className="animate-spin" />`), chama `api.briefings.extract`,
toast de sucesso/erro via `useToast`, invalida `queryClient.invalidateQueries(["briefings"])`.

**Sidebar nav:** adicionar link `/briefings` com ícone `FileText` se ainda não existir.

## 4. Frontend — `/prospecting`

**Arquivo:** `apps/web/src/app/(dashboard)/prospecting/page.tsx`

### Layout

```
Prospecting

┌─────────────────────────────────────────────────────────┐
│ [Categoria: input] [Cidade: input] [Agente: select] [▶] │
└─────────────────────────────────────────────────────────┘

Histórico de Buscas
┌──────────────┬──────────────┬────────┬──────────┬──────────┐
│ Categoria    │ Cidade       │ Leads  │ Status   │ Data     │
├──────────────┼──────────────┼────────┼──────────┼──────────┤
│ restaurantes │ São Paulo    │ 47     │COMPLETED │ 12/06    │
└──────────────┴──────────────┴────────┴──────────┴──────────┘
```

**Prospecting tem 3 sub-seções via Tabs:**

**Tab 1 — Nova Busca:** Form com campos `categories[]` (chips adicionáveis) + `city` +
`state` (2 chars) + `radiusKm` (slider 5-100km) + `minScore` (default 40) + agente
HUNTER (select). Submit → `POST /api/v1/prospecting/search-maps`. Zod client-side valida
antes de enviar.

**Tab 2 — Fila (Queue):** Tabela `GET /api/v1/prospecting/queue` — leads com status
PROSPECTED, PII mascarado (já vem mascarado da API). Colunas: `businessName | score |
source | data | pendingHitl`. Badge "HITL" amber se `pendingHitl === true`.

**Tab 3 — Configuração:** Form `GET /api/v1/prospecting/config` + `PATCH /api/v1/prospecting/config`.
Editar `categories, region, minScore, scheduleTime, scheduleDays`. Read-only: `lastRunAt, nextRunAt,
mapsQuotaRemaining`.

**api client additions:**

```typescript
prospecting: {
  searchMaps: (data, token) => request("/prospecting/search-maps", { method:"POST", ... }),
  queue: (token) => request("/prospecting/queue", { token }),
  getConfig: (token) => request("/prospecting/config", { token }),
  updateConfig: (data, token) => request("/prospecting/config", { method:"PATCH", ... }),
}
```

**Empty state queue:** ícone `Search` + "Nenhum lead na fila".
